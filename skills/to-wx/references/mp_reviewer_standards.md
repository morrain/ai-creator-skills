# 微信公众号长文审稿标准手册 (WeChat Article Reviewer Standards)

本文档为 **微信长文审稿 SubAgent (`mp_article_reviewer`)** 审查微信公众号长文（`mp_article.html`）的唯一指导标准。审稿人必须客观严谨打分并给出结构化裁决。

---

## 审查维度与判定标准

### 一、 核心否决项 (Fatal Rejection Rules - 一票否决)

出现以下任意情况，必须直接裁决为 **`[REJECT]`**：

1. **Markdown 表格残留**：
   - 全文包含任何形式的 `| col1 | col2 |` 原生 Markdown 表格语法。
   - 原因：原生表格在微信公众号移动端极其丑陋且严重破坏滑动体验，必须完全重构为卡片或列表。

2. **核心知识点缺失**：
   - 相比于 `<article-slug>.md` 母版长文，丢失了核心干货、关键代码逻辑或重要论点。

3. **篡改原文或擅自插入提炼总结卡片 (一票否决)**：
   - 正文包含了原文中未出现的 AI 提炼总结卡片、新增段落，或擅自修改、增删了原文句子。高亮提示必须且仅能通过 `<span style="...">` 标签精准包覆原文已有词句。

---

## 二、 排版与移动端视觉体验标准 (Mobile UX & Layout Standards)

审查排版是否达到微信爆款长文标准：

1. **表格解构与 HTML 内联卡片化**：
   - **对比场景**：是否使用双色 HTML 浅底边框卡片（`🔴 传统痛点` vs `🟢 新架构优势`）重构？
   - **参数场景**：是否使用 Key-Value 属性卡片容器（`📌` / `🔹`）重构？
   - **流程场景**：是否转为带图标的步骤列表（`🚀 阶段一`）？

2. **视觉卡片分层与 HTML 内联组件**：
   - **二级/三级标题**：二级标题是否采用居中 + 浅蓝胶囊与下划线；三级标题是否采用靠左对齐 (`text-align: left`) + 左侧极光蓝竖向边框 (`border-left: 3.5px solid #10AEFF`)，杜绝多行标题两侧符号悬空不对称现象？
   - **金句高亮**：章节末尾是否使用 `💡` HTML 内联引用卡片包裹爆款金句？
   - **结尾引导**：底部是否有良好的互动/关注 HTML 引导卡片？

3. **正文插图与图注组件**：
   - 识别 `assets/illustration_*.md` 锚点，正文中是否完整引入了图片路径（`images/illustration_*.png`）？
   - 图片是否统一置于 `text-align: center` 居中容器中、设置 `width: 100%; max-width: 100%` 统一尺寸，且下方带有显式居中的灰色斜体中文图注说明（`💡 图 1：...`）？

4. **阅读节奏与代码块处理**：
   - 段落是否保持在 2-4 行以内，字号、行高（1.75+）与字间距设置合理？
   - **代码块与过渡重构**：若保留代码块，是否精炼且附有中文行内注释；若剥离代码块，剥离处的上下文连接是否顺畅自然（用通俗自然语言填补了代码原本承担的逻辑推演，无生硬断层感）。

5. **正文段落适度点睛高亮 (Moderate Highlighting)**：
   - 检查高亮/下划线标注是否精炼适度（每个二级标题小节控制在 2~3 处点睛即可），避免高亮过多造成密密麻麻的视觉拥挤与疲劳。

---

## 三、 审稿输出报告模板

审稿 SubAgent 必须输出结构化报告：

```markdown
# 审查结果：[PASS] 或 [REJECT]

## 评分明细 (满分 100 分)
- 表格解构与 HTML 内联卡片化 (30分)：XX分
- 插图嵌合与图注组件规范 (20分)：XX分
- 移动端卡片分层与视觉节奏 (30分)：XX分
- 母版干货忠实度 (20分)：XX分

## 诊断意见与修正要求
1. [表格项] ...
2. [排版项] ...
3. [插图项] ...
```
